SPRINT 7
========

GOAL

Provide rigorous scientific validation of SecureFlow and
demonstrate its effectiveness against existing state-of-the-art
static analysis tools.

This sprint transforms the project from a software engineering
prototype into a research-grade system suitable for publication.

------------------------------------------------------------
PART A
DATASET GENERATOR
------------------------------------------------------------

OBJECTIVE

Create a reproducible benchmark dataset containing both
vulnerable and secure Python programs.

DELIVERABLES

1. Synthetic vulnerability generator.
2. Secure code generator.
3. Dataset metadata.
4. Ground truth labels.

DATASET CATEGORIES

Category A

Direct SQL Injection

Example:

user = request.form.get("user")
cursor.execute(
    "SELECT * FROM users WHERE name='" + user + "'"
)

Label:

VULNERABLE

------------------------------------------------------------

Category B

Interprocedural SQL Injection

Example:

def get_user():
    return request.form.get("user")

user = get_user()

cursor.execute(
    "SELECT * FROM users WHERE name='" + user + "'"
)

Label:

VULNERABLE

------------------------------------------------------------

Category C

Sanitized Input

Example:

user = sanitize(
    request.form.get("user")
)

cursor.execute(
    "SELECT * FROM users WHERE name='" + user + "'"
)

Label:

SAFE

------------------------------------------------------------

Category D

Parameterized Queries

Example:

user = request.form.get("user")

cursor.execute(
    "SELECT * FROM users WHERE name=?",
    (user,)
)

Label:

SAFE

------------------------------------------------------------

Category E

Complex Flow Cases

Examples:

- nested functions
- loops
- conditionals
- multiple assignments
- aliases
- recursive propagation

------------------------------------------------------------

REQUIREMENTS

Dataset size:

Minimum:
200 programs

Recommended:
500+ programs

Store labels in JSON.

Example:

{
    "file": "case_001.py",
    "label": "VULNERABLE",
    "vulnerability": "SQLI",
    "source_line": 3,
    "sink_line": 8
}

OUTPUT

dataset/
dataset_generator.py
dataset_metadata.json

PART B
BENCHMARK SUITE
------------------------------------------------------------

OBJECTIVE

Build an automated benchmarking framework capable of
executing SecureFlow and competing tools on the same dataset.

DELIVERABLES

1. Benchmark runner.
2. Result collector.
3. Unified report format.

TOOLS TO EVALUATE

SecureFlow
Bandit
Semgrep
Pyre/Pysa

BENCHMARK PIPELINE

For each sample:

1. Run SecureFlow
2. Run Bandit
3. Run Semgrep
4. Run Pysa
5. Collect results
6. Compare against ground truth

OUTPUT FORMAT

{
    "tool": "SecureFlow",
    "file": "case_001.py",
    "prediction": "VULNERABLE",
    "ground_truth": "VULNERABLE",
    "execution_time_ms": 25
}

OUTPUT

benchmark_runner.py
benchmark_results.json

PART C
METRICS ENGINE
------------------------------------------------------------

OBJECTIVE

Compute scientific evaluation metrics.

DELIVERABLES

1. Confusion matrix.
2. Precision.
3. Recall.
4. F1 Score.
5. Accuracy.
6. False Positive Rate.
7. False Negative Rate.

CONFUSION MATRIX

TP
FP
TN
FN

FORMULAS

Precision

TP / (TP + FP)

Recall

TP / (TP + FN)

F1 Score

2 * Precision * Recall
----------------------
Precision + Recall

Accuracy

(TP + TN)
---------
Total

False Positive Rate

FP / (FP + TN)

False Negative Rate

FN / (FN + TP)

OUTPUT

metrics.py
evaluation_report.json
